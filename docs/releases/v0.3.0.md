The Pluto joins Corvus: a small program that runs on a PlutoSDR-family board (ADALM-Pluto, Pluto+) and
drives its AD936x directly, sweeping 70 MHz–6 GHz at about **130 GHz/s, 22 full passes a second** over
Gigabit Ethernet. The RFOne and Airspy firmware and the host libraries are unchanged from v0.2.0 (the images
rebuild byte for byte).

> **Unofficial.** Corvus is not affiliated with, endorsed by or supported by HydraSDR, Airspy,
> Great Scott Gadgets or Analog Devices. **Flashing unofficial firmware is at your own risk.** Back up
> your board's flash first, and read [firmware/README.md](https://github.com/auggiesoft/corvus/blob/v0.3.0/firmware/README.md#flashing).

## What's new

- **Pluto sweep (`corvus-pluto`).** One static ARM binary that runs on the board next to its firmware
  (no flashing) and serves tagged sweep blocks to Corvus Sweep over the network. It needs firmware with
  ADI's capture path (ADI's stock firmware, or F5OEO's PlutoDVB2 on a Pluto+); Maia SDR's firmware can't hand
  samples to a program. Install with `install.sh <board address>`; on PlutoDVB2 it also starts at every boot.
  The board's normal streaming (libiio, SDR++, GNU Radio) keeps working whenever Corvus isn't connected.
- **Fast mode.** Instead of retuning through the Linux driver (~1.1 ms a step), `corvus-pluto` calibrates
  each step's synthesizer settings once, then switches between them with the chip's fastlock profiles over
  direct SPI: one register write, settled in about a microsecond. It writes the gain tables itself at the
  1.3 and 4 GHz band edges and queues each capture block after the switch, so nothing is wasted. Levels
  match the driver path to within a few hundredths of a dB (median). Measured on a Pluto+, 40 MHz steps:

  | | steps/s | GHz/s | passes/s (70–6000 MHz) |
  |---|---|---|---|
  | fast mode, Gigabit Ethernet | ~3,300 | ~130 | ~22 |
  | fast mode, the USB network link | ~1,900 | ~76 | ~13 |
  | through the driver (the fallback) | ~650 | ~26 | ~4.4 |

  Fast mode needs nothing else driving the AD936x while it sweeps; it notices if something does and
  carries on through the driver. On PlutoDVB2, `STOP_DATV=1 install.sh` switches off the DATV services
  that poll the chip. Details: [firmware/pluto/README.md](https://github.com/auggiesoft/corvus/blob/v0.3.0/firmware/pluto/README.md).
- **Corvus Sweep: `--pluto HOST`** (or `--board pluto` for a Pluto on its USB network link at
  192.168.2.1). Two rates: 61.44 MSPS (40 MHz steps by default, up to 50) and 30.72 MSPS (finer bins).
  Passes go back and forth. Blocks arrive 12-bit packed. The device chip says whether the board sweeps
  in fast mode, and if not, why. The learned flatness correction takes the per-step ripple from about
  3.7 dB to 0.5 dB.
- **`--board pluto --sim`** simulates a Pluto with fast mode's timing, so you can try it without one.

## Files

| File | What it is |
|---|---|
| `corvus-sweep-v0.3.0-windows-x64.zip` | Corvus Sweep for Windows 10/11 x64: unzip and run `corvus-sweep.exe`; `--sim` needs no radio |
| `corvus-sweep-v0.3.0-linux-x86_64.tar.gz` | Corvus Sweep for Linux. Unpack and run `./corvus-sweep`; the two libraries ride along for `--usb lib` |
| `corvus-pluto-v0.3.0-armv7.tar.gz` | **new:** the Pluto's on-board sweep program (ARMv7 Linux, static) with `install.sh` and `plutodvb2-quiet.sh` |
| `corvus-fw-v1.0.2-sweep5-rfone.bin` | RFOne firmware (v1.0.2 plus sweep mode), same as v0.1.0 |
| `corvus-fw-v1.0.0-rc10-6-8-gcf1a374-sweep5-airspy.bin` | Airspy R2 **and** Mini firmware, same as v0.1.0 |
| `corvus-host-v0.3.0-linux-x86_64.tar.gz` | libhydrasdr and libairspy with the sweep API, plus the `hydrasdr_*` and `airspy_*` tools |
| `corvus-libhydrasdr-v0.3.0-windows-x64.zip` | libhydrasdr for Windows (MinGW build) |
| `SHA256SUMS` | checksums of all of the above |

Corvus Sweep needs a Vulkan or GL driver (DirectX 12 on Windows). The Linux host tools
still need libusb-1.0. Boards on stock firmware work too, with a slower PC-driven sweep.

Source for every binary, including the GPL firmware and tools, is this repository at tag `v0.3.0`;
each archive's NOTICE.txt lists the licences. `corvus-pluto` includes Analog Devices' AD936x gain tables
from their no-OS driver (BSD-3-Clause, `LICENSE-no-OS.txt` in its archive).
