The Pluto runs on F5OEO's Tezuka firmware too, fast mode included. Corvus Sweep, the RFOne and Airspy
firmware and the host libraries are unchanged from v0.3.1 apart from the version number.

> **Unofficial.** Corvus is not affiliated with, endorsed by or supported by HydraSDR, Airspy,
> Great Scott Gadgets or Analog Devices. **Flashing unofficial firmware is at your own risk.** Back up
> your board's flash first, and read [firmware/README.md](https://github.com/auggiesoft/corvus/blob/v0.3.2/firmware/README.md#flashing).

## What's new

- **Tezuka support (`corvus-pluto` 0.2.2).** Tested on a Pluto+ with Tezuka v0.3.24 (kernel 6.12, Maia SDR
  alongside): fast mode at ~2,700 steps/s over Ethernet at 61.44 MSPS (109 GHz/s, 70–6000 MHz), the driver
  path at ~440. Tezuka's kernel is somewhat slower than PlutoDVB2's on the same board (3,340 there).
- **Pollers paused while sweeping.** Tezuka's web-dashboard telemetry (`api_controller.sh`) and PTT watcher
  (`watchconsoletx.sh`) read and write the AD936x every second or two, which kept fast mode off and could
  disturb the extended tuning's register writes. `corvus-pluto` now pauses them for the length of a sweep
  and resumes them on STOP, a new configuration or a disconnect (and at start-up, if an earlier run was
  killed mid-sweep). They're matched by exact script path; nothing else is touched. The dashboard's
  figures freeze while Corvus sweeps.
- **Newer kernels:** fast mode finds the SPI controller from the radio's own sysfs path (6.12 moved it from
  `amba/` to `axi/`).
- **30.72 MSPS ceiling explained:** a board in 2R2T mode (both RX channels on) can't go past 30.72 MSPS.
  The Pluto README says how to tell and what the bootloader's `mode=1r1t` does.
- `plutodvb2-quiet.sh` now does nothing on firmware other than PlutoDVB2.

## Files

| File | What it is |
|---|---|
| `corvus-sweep-v0.3.2-windows-x64.zip` | Corvus Sweep for Windows 10/11 x64: unzip and run `corvus-sweep.exe`; `--sim` needs no radio |
| `corvus-sweep-v0.3.2-linux-x86_64.tar.gz` | Corvus Sweep for Linux. Unpack and run `./corvus-sweep`; the two libraries ride along for `--usb lib` |
| `corvus-pluto-v0.3.2-armv7.tar.gz` | the Pluto's on-board sweep program (ARMv7 Linux, static), `corvus-pluto` 0.2.2, with `install.sh` and `plutodvb2-quiet.sh` |
| `corvus-fw-v1.0.2-sweep5-rfone.bin` | RFOne firmware (v1.0.2 plus sweep mode), same as v0.1.0 |
| `corvus-fw-v1.0.0-rc10-6-8-gcf1a374-sweep5-airspy.bin` | Airspy R2 **and** Mini firmware, same as v0.1.0 |
| `corvus-host-v0.3.2-linux-x86_64.tar.gz` | libhydrasdr and libairspy with the sweep API, plus the `hydrasdr_*` and `airspy_*` tools |
| `corvus-libhydrasdr-v0.3.2-windows-x64.zip` | libhydrasdr for Windows (MinGW build) |
| `SHA256SUMS` | checksums of all of the above |

Update the board with the new `corvus-pluto` (`install.sh <board address>`); Corvus Sweep 0.3.2 works with
`corvus-pluto` 0.2.0 and later. Corvus Sweep needs a Vulkan or GL driver (DirectX 12 on Windows). Source for every
binary is this repository at tag `v0.3.2`; each archive's NOTICE.txt lists the licences.
