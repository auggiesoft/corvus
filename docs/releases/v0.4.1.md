Corvus Sweep reaches any radio SoapySDR can open, and the Pluto's `corvus-pluto` recovers from other
programs' settings. The RFOne and Airspy firmware and the host libraries are unchanged from v0.4.0.

> **Unofficial.** Corvus is not affiliated with, endorsed by or supported by HydraSDR, Airspy,
> Great Scott Gadgets or Analog Devices. **Flashing unofficial firmware is at your own risk.** Back up
> your board's flash first, and read [firmware/README.md](https://github.com/auggiesoft/corvus/blob/v0.4.1/firmware/README.md#flashing).

## What's new

- **SoapySDR radios.** With SoapySDR 0.8 installed, every radio its modules find (RTL-SDR, LimeSDR, SDRplay,
  BladeRF, USRPs such as the B210, …) shows in the radio picker, or `--soapy ARGS` picks one
  (`--soapy driver=rtlsdr`). Corvus Sweep loads libSoapySDR when it needs it and never links it: without it,
  nothing changes. The PC sweeps the radio step by step, dropping what's in flight after each retune, and
  the engine treats it like the Pluto: two looks hide its DC spike and images, the passband learner learns its
  filter, the health check reads its headroom. Slower than a board's own sweep (measured on the FM band:
  70–76 steps/s for an RFOne or Airspy Mini through their SoapySDR modules, against 520–780 natively), with
  the same signals and floor. [app/README.md](https://github.com/auggiesoft/corvus/blob/v0.4.1/app/README.md#getting-soapysdr)
  says how to get SoapySDR and the modules on Linux and Windows (PothosSDR or radioconda), and the USB
  drivers each radio needs.
- **`corvus-pluto` 0.2.4.** Every configuration now turns the AD936x's FIR decimator off and its RX LO on.
  SoapyPlutoSDR (and so SDR++, GQRX and the like through it) leaves the FIR on, which stopped `corvus-pluto`
  setting 61.44 MSPS, and powers the RX LO down when it closes, which left the next sweep deaf. Update the
  board with `install.sh <board address>`.

## Files

| File | What it is |
|---|---|
| `corvus-sweep-v0.4.1-windows-x64.zip` | Corvus Sweep for Windows 10/11 x64: unzip and run `corvus-sweep.exe`; `--sim` needs no radio |
| `corvus-sweep-v0.4.1-linux-x86_64.tar.gz` | Corvus Sweep for Linux. Unpack and run `./corvus-sweep`; the two libraries ride along for `--usb lib` |
| `corvus-pluto-v0.4.1-armv7.tar.gz` | the Pluto's on-board sweep program (ARMv7 Linux, static), `corvus-pluto` 0.2.4, with `install.sh` and `plutodvb2-quiet.sh` |
| `corvus-fw-v1.0.2-sweep5-rfone.bin` | RFOne firmware (v1.0.2 plus sweep mode), same as v0.1.0 |
| `corvus-fw-v1.0.0-rc10-6-8-gcf1a374-sweep5-airspy.bin` | Airspy R2 **and** Mini firmware, same as v0.1.0 |
| `corvus-host-v0.4.1-linux-x86_64.tar.gz` | libhydrasdr and libairspy with the sweep API, plus the `hydrasdr_*` and `airspy_*` tools |
| `corvus-libhydrasdr-v0.4.1-windows-x64.zip` | libhydrasdr for Windows (MinGW build) |
| `SHA256SUMS` | checksums of all of the above |

Remote operation is unchanged and works between v0.4.0 and v0.4.1, except that a v0.4.0 window can't show a
v0.4.1 server's SoapySDR radio (it doesn't know that kind of board): update both for that.
Corvus Sweep needs a Vulkan or GL driver (DirectX 12 on Windows). Source for every binary is this repository
at tag `v0.4.1`; each archive's NOTICE.txt lists the licences.
