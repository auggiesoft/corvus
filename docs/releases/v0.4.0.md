Corvus Sweep goes remote: share a radio from one machine and drive it from another, in the same window. Also
a health check, and on the Pluto two looks at every frequency and a live trace that steadies the noise but
lets bursts through. The firmware, the host libraries and `corvus-pluto` (0.2.3) are unchanged from v0.3.3.

> **Unofficial.** Corvus is not affiliated with, endorsed by or supported by HydraSDR, Airspy,
> Great Scott Gadgets or Analog Devices. **Flashing unofficial firmware is at your own risk.** Back up
> your board's flash first, and read [firmware/README.md](https://github.com/auggiesoft/corvus/blob/v0.4.0/firmware/README.md#flashing).

## What's new

- **Remote operation.** One Corvus Sweep owns the radio and shares it; another, on any machine (Linux or
  Windows), connects by address and PIN and drives it with the same controls.
  - **Share:** `corvus-sweep --serve` runs without a window. Or tick *Share this radio* in the radio picker
    (or start with `--share`): the window keeps working, and a client can drive it too. It listens on every
    interface, port 30434, with a six-digit PIN (`--pin`, else a random one, printed at start).
  - **Connect:** the radio picker lists servers found on the LAN and ones used before, and takes an address
    and PIN; or `--connect HOST --pin PIN`. The window takes the server's board, sweep settings and waterfall
    history, and while connected the picker lists the server's radios and switches between them. Levels,
    colours and which traces are drawn stay each window's own.
  - **The server keeps sweeping** between clients, with the last settings, and keeps the history for the next
    one. One client at a time.
  - **Light on the network:** the traces come reduced to the client's view, the waterfall in 0.5 dB steps;
    about 250–330 kB/s for a full-width window, 0.4–1 MB of history on connecting. CSV export fetches the
    full-resolution spectrum from the server.
  - **Security:** the PIN never crosses the wire (challenge-response, HMAC-SHA256), and repeated wrong PINs
    make logins wait. Nothing is encrypted: off the LAN, use a VPN such as Tailscale. The server's firewall
    must let TCP 30434 in (and UDP 30434 for discovery).
- **Health check.** The Headroom card shows the strongest sample against full scale and flags clipping (the
  status bar names the steps and says to lower the gain); on the Pluto it also measures image rejection and
  points out lines that are another signal's mirror about the LO. `--gain N` sets the gain from the command
  line.
- **Two looks (Pluto, on by default; engine card or `--looks 1|2`).** Steps half as far apart, each still
  measuring its full width, so every frequency is seen from two LOs and the cleaner look wins. Strong
  signals' images and the dip at each LO go, and the floor is steadier, at half the speed (70–6000 MHz:
  ~9 passes a second over Ethernet).
- **A steadier live trace (on by default; Display card or `--smooth SECS`, 0 = off).** Each bin's noise is
  averaged over about a second, while anything well above its usual level shows at once and falls back
  quickly when it ends. Off-air on the Pluto: the floor's wander 2.3 → 0.65 dB, bursts 15 dB up shown at
  full level 98–100 % of the time.
- `--csv` gains the unsmoothed value as a column; `--csv-every SECS` writes snapshots.

## Files

| File | What it is |
|---|---|
| `corvus-sweep-v0.4.0-windows-x64.zip` | Corvus Sweep for Windows 10/11 x64: unzip and run `corvus-sweep.exe`; `--sim` needs no radio |
| `corvus-sweep-v0.4.0-linux-x86_64.tar.gz` | Corvus Sweep for Linux. Unpack and run `./corvus-sweep`; the two libraries ride along for `--usb lib` |
| `corvus-pluto-v0.4.0-armv7.tar.gz` | the Pluto's on-board sweep program (ARMv7 Linux, static), `corvus-pluto` 0.2.3 (unchanged), with `install.sh` and `plutodvb2-quiet.sh` |
| `corvus-fw-v1.0.2-sweep5-rfone.bin` | RFOne firmware (v1.0.2 plus sweep mode), same as v0.1.0 |
| `corvus-fw-v1.0.0-rc10-6-8-gcf1a374-sweep5-airspy.bin` | Airspy R2 **and** Mini firmware, same as v0.1.0 |
| `corvus-host-v0.4.0-linux-x86_64.tar.gz` | libhydrasdr and libairspy with the sweep API, plus the `hydrasdr_*` and `airspy_*` tools |
| `corvus-libhydrasdr-v0.4.0-windows-x64.zip` | libhydrasdr for Windows (MinGW build) |
| `SHA256SUMS` | checksums of all of the above |

Servers and clients need the same remote protocol: 0.4.0 on both (a client says so when a server speaks another). Corvus Sweep
needs a Vulkan or GL driver (DirectX 12 on Windows). Source for every binary is this repository at tag
`v0.4.0`; each archive's NOTICE.txt lists the licences.
