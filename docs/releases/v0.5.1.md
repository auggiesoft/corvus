Corvus Sweep fixes lost steps on Windows with a fast screen, gets a live view on every board but the HackRF,
and sweeps RTL-SDR dongles three times as fast. The firmware (sweep7) and `corvus-pluto` (0.2.4) are unchanged
from v0.5.0.

> **Unofficial.** Corvus is not affiliated with, endorsed by or supported by HydraSDR, Airspy,
> Great Scott Gadgets or Analog Devices. **Flashing unofficial firmware is at your own risk.** Back up
> your board's flash first, and read [firmware/README.md](https://github.com/auggiesoft/corvus/blob/v0.5.1/firmware/README.md#flashing).

## What's new

- **Lost steps on Windows fixed: update recommended.** The frame rate setting asked for a frame every 1/60 s
  but didn't stop others, so on a screen without vsync the window drew at 250–350 fps. Each frame holds the
  spectrum the receiving side writes into, and that side fell behind: a Pluto+ at 30.72 MSPS in a maximized
  window lost about 14,000 steps in 45 s (counted under Health as gaps and drops), where `--headless` lost
  none. The setting is now a ceiling, and the receiving side takes a backlog in one go instead of a block at a
  time. On the same Windows PC: 0 lost at 30.72 and 61.44 MSPS, 59 of 60 fps, half the CPU, and a 10-minute
  run with resizing, dragging and the 3D waterfall stayed clean. Linux was hidden from this by vsync at 60 Hz.
  On v0.5.0, setting the frame rate to 30 avoids it.
- **Live view on every board but the HackRF.** Live (the Range card's switch, or L over the spectrum) stays on
  one frequency and shows every block as an update, as the Pluto has done since v0.4. On the RFOne and Airspys the board streams normally,
  so it doesn't need the sweep firmware (tested on an R2 with stock firmware): spans of 10, 6, 3 and 1 MHz on the RFOne, 9, 6, 3 and
  1 on the R2, 4, 2 and 1 on the Mini. An RTL-SDR or a SoapySDR radio offers the usable width of each of its
  rates (RTL-SDR: 1.8, 1.5 and 0.7 MHz). Measured: an Airspy R2 2,441 updates a second on Linux and Windows
  (stock and Corvus firmware), an RTL-SDR ~590 at 2.4 MSPS. **Not yet run** on an RFOne or a Mini.
- **RTL-SDR dongles sweep three times as fast,** with [corvus-rtl v0.2.0](https://github.com/auggiesoft/corvus-rtl/releases/tag/v0.2.0):
  its librtlsdr retunes in 11.5 ms instead of 50.6 (5 USB transfers instead of 22: tuner registers are
  written only when they change, the I2C repeater is switched only when needed, and the VCO fine-tune value
  is reused from the last lock check). 52 steps a second at 2.4 MSPS, 24–1766 MHz in about 37 s (v0.5.0: 17
  and two minutes). Stations land on the same frequencies at the same levels. Corvus Sweep downloads the new
  library the first time an RTL-SDR is chosen (about 0.3 MB, checked against its SHA-256). **Still not run on
  Windows**; please open an issue if the library or the driver installer misbehaves there.
- **RTL-SDR fixes.** 1.024 MSPS (and any rate narrower than 1 MHz) crashed when a plan was made; it now
  plans. The averaging and smoothing times are right on an RTL-SDR (its block clock didn't count the time
  spent retuning). A full-range plan's last step could land just above what the tuner reaches, which showed as
  one gap per pass; plans now hold only steps the tuner can reach.
- **The waterfall shows the readings as measured.** Live trace smoothing (Settings) smoothed the waterfall
  too, so bursts were dimmed and stretched there; it now changes only the live trace.
- **A live span change no longer counts a lost step.** On a Pluto, each span that changed the sample rate
  counted one gap and showed "Steps were lost" for 10 s.

## Files

| File | What it is |
|---|---|
| `corvus-sweep-v0.5.1-windows-x64.zip` | Corvus Sweep for Windows 10/11 x64: unzip and run `corvus-sweep.exe`; `--sim` needs no radio |
| `corvus-sweep-v0.5.1-linux-x86_64.tar.gz` | Corvus Sweep for Linux. Unpack and run `./corvus-sweep`; the two libraries ride along for `--usb lib` |
| `corvus-pluto-v0.5.1-armv7.tar.gz` | the Pluto's on-board sweep program (ARMv7 Linux, static), `corvus-pluto` 0.2.4 (unchanged), with `install.sh` and `plutodvb2-quiet.sh` |
| `corvus-fw-v1.0.2-sweep7-rfone.bin` | RFOne firmware (v1.0.2 plus sweep mode), unchanged |
| `corvus-fw-v1.0.0-rc10-6-8-gcf1a374-sweep7-airspy.bin` | Airspy R2 **and** Mini firmware, unchanged |
| `corvus-host-v0.5.1-linux-x86_64.tar.gz` | libhydrasdr and libairspy with the sweep API, plus the `hydrasdr_*` and `airspy_*` tools (unchanged) |
| `corvus-libhydrasdr-v0.5.1-windows-x64.zip` | libhydrasdr for Windows (MinGW build, unchanged) |
| `SHA256SUMS` | checksums of all of the above |

The RTL-SDR files aren't part of this release: they're corvus-rtl's
[v0.2.0](https://github.com/auggiesoft/corvus-rtl/releases/tag/v0.2.0), under librtlsdr's licence (GPL-2.0)
and libwdi's (LGPL-3.0).

Remote operation works between v0.5.0 and v0.5.1. Corvus Sweep needs a Vulkan or GL driver (DirectX 12 on
Windows). Source for every binary is this repository at tag `v0.5.1`; each archive's NOTICE.txt lists the
licences.
